# Implementation roadmap

The release objectives are dependency gates with no fixed dates.

| Version | Delivery gate |
| --- | --- |
| v0.0.1 | Freeze legacy snapshot, verify migration inventory, approve foundation and subsystem specifications |
| v0.1.0 | Safe Rust foundation, durable embedded storage, runtime, resource admission and CLI |
| v0.2.0 | Security boundaries, scoped Git/GitHub integration, verified instructions and pinned repository worktrees |
| v0.3.0 | Governed local/remote model inference, model lifecycle and context assembly |
| v0.4.0 | Persistent assignment and workflow execution, agents, pause/resume and reconciliation |
| v0.5.0 | Exact 30-file Vimbai documentation scenario, independent review and auditable PR |
| v0.6.0 | Patch planning, builds, tests, debugging and scoped verification |
| v0.7.0–v0.9.0 | Editor integration, native Studio and reliability/hardware matrix |
| v1.0.0 | Personal platform passes G01–G16 |
| v1.5.0 | Embedded inference and advanced knowledge |
| v2.0.0 | Authorized compute mesh and distributed recovery |
| v3.0.0 | Advanced SDK, enterprise governance and governed evolution |

Creation order follows foundation/configuration/identity/storage/events → runtime/resources → governance/sandbox → repositories → intelligence → assignments/agents → documentation and verification → engineering/application adapters. Traits may start as internal modules where the eventual boundary is preserved. Optional capabilities remain disabled until their own integration and acceptance evidence exists.
