# Pinned document inventory

**ZIP-DOCUMENTATION-INVENTORY-001 · v1.1 candidate · Owner** Documentation maintainers

**Planned source** `crates/documentation/src/inventory.rs`

Take one verified repository snapshot, approved path scope and pinned instruction context. Walk bounded tree pages by the original commit, preserving exact path, mode and object ID. For each named target record role, expected existing blob or verified absence, eligibility, applicable instruction bundle, source and normative dependencies, classification and chosen review action. A rename or branch advance does not change the pinned inventory. Unreadable or incomplete evidence remains explicitly unknown and cannot establish a missing file or scoped edit.

Sort target paths by canonical path bytes. Keep the complete dependency graph for planning. Validate referenced existing documents before counting their dependencies fulfilled. For substantive dependencies between new documents use stable topological order and block unresolved cycles. Mere cross-links can use approved anchor obligations under [validation](validation.md). Freeze approved target order and evidence expectations with the plan. Expanding a path or substituting a target requires a revised plan and any required owner authority.

**ZIP-DOCUMENTATION-INVENTORY-T01.** Move a branch after inventory starts and verify every page still uses the original commit. A skipped tree page cannot prove a file absent.
