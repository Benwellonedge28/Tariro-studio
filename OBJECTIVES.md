# Zipporah objectives

Zipporah provides persistent, governed software engineering infrastructure on a user-owned computer. The first acceptance workload is a Vimbai documentation assignment on a 16 GiB laptop. The platform must also provide a controlled route to private servers, native inference and distributed compute.

| ID | Objective | Evidence required |
| --- | --- | --- |
| OBJ-001 | Own the engineering runtime | A clean native install can create, execute, verify and recover a local assignment. |
| OBJ-002 | Reduce dependence on paid AI | Deterministic stages and a compatible local model complete the reference workload without paid calls. |
| OBJ-003 | Cover the development lifecycle | Release gates independently demonstrate documentation, implementation, build, test, review and maintenance. |
| OBJ-004 | Operate locally and offline | A network-disabled acceptance run performs all capabilities advertised as local. |
| OBJ-005 | Support arbitrary languages | Unregistered languages receive explicit text-only capability and can add an isolated adapter. |
| OBJ-006 | Understand existing and future repos | A manifest-free repo can be pinned, inspected and indexed with provenance. |
| OBJ-007 | Persist autonomous assignments | Kill at document 17 and resume at 18 using verified checkpoints. |
| OBJ-008 | Enforce human authority | Scope, expiry and revocation tests block forbidden effects. |
| OBJ-009 | Adapt to available hardware | Personal profile admits one generation model and prevents memory overcommit. |
| OBJ-010 | Exchange models/providers | An adapter contract test runs the same request through two compatible providers. |
| OBJ-011 | Prevent fabricated outcomes | Negative tests prove unverifiable claims cannot produce completion. |
| OBJ-012 | Provide reproducibility and audit | Replay resolves original input, policy, toolchain, evidence and effect IDs. |
| OBJ-013 | Enable distributed execution | An expired or partitioned worker cannot publish authoritative results. |
| OBJ-014 | Support governed evolution | Self-improvement proposals pass independent review and normal release approval. |
| OBJ-015 | Preserve user data ownership | Demonstrate scoped export, clean restore and retention enforcement without required external storage. |
| OBJ-016 | Sustain long-term continuity | Maintain versioned formats, migration tests and a documented deprecation path. |

Each release declares the objectives and capability evidence it satisfies. See [ROADMAP.md](ROADMAP.md) for sequencing and [VERIFICATION.md](VERIFICATION.md) for acceptance.
